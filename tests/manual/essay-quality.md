# 새 대화에서의 초안 품질 평가

이 문서는 반복 실행 시나리오다. 작성 자체는 실행 증거가 아니다. 자동 계약 테스트는 `tests/test_essay_quality.py`로 수행하며 아래 생성 품질 평가는 별도 실행과 판정이 필요하다.

## 입력과 실행

정보 부족·부분초안 평가는 [기존 가상 입력](fixtures/essay-quality-input.md), 이야기 연결 평가는 [연결 검토 입력](fixtures/essay-coherence-input.md)을 각각 별도 대화에서 사용한다. 각 평가 대상에는 현재 SKILL.md와 그 참조 문서 및 해당 입력 하나만 제공한다. 이 평가 기준이나 기대 답, 과거 실패 설명은 생성 전에 주지 않는다. 작성된 문장이 동일한지를 평가하지 않는다.

1. 실제 취업 폴더와 분리한 임시 워크스페이스에서 가상 입력의 요청을 실행한다. 네트워크·외부 저장·실제 개인 자료는 사용하지 않는다.
2. 같은 입력을 서로의 결과를 보지 않는 새 대화에서 3회 실행한다. 이전 대화의 요약이나 작성본을 넘기지 않는다. 별도 작업이나 에이전트 생성은 해당 환경의 사용자 권한을 따른다.
3. 사용자가 실제로 쓰는 다른 환경에서도 같은 입력으로 반복한다. 스킬 커밋·모델·설정·가용 도구·훅 사용 여부·템플릿 버전을 기록한다. 환경 비교를 위해 실제 설정을 임의로 변경하지 않는다.
4. 자동 검사 실행이 불가능한 환경이라면 내용 검토와 본문 작성은 계속하되 자동 검사 미실행이 명시되는지 확인한다.
5. 각 실행의 초안·작성 설계·검토 기록·사용자 확인 질문·검사 결과를 임시 결과 폴더에 보관한다. 모든 체크박스가 true인지로 내용 평가를 대체하지 않는다.

## 첫 응답 평가

| 항목 | 통과 기준 |
| --- | --- |
| 문항 1의 적합성 | F1의 목표 축소를 높은 목표 달성으로 단정하지 않는다. 원본과 대안을 검토한 뒤 부족한 목표 설정 사실을 질문하고 해당 답변은 보류한다. F2/F3에도 높은 목표를 스스로 설정한 근거가 없으므로 임의 전환으로 통과시키지 않는다. |
| 문항 2의 직접 답변 | 실제 수행한 준비와 앞으로의 기여를 구분한다. 사례 수와 문단 순서는 자유지만 각 사례가 답변에 기여한다. |
| 독해 가능성 | 본문에서 문제·행동·결과를 요약하는 데 그치지 않고 왜 그 행동이 필요했고 결과가 무엇에 답하는지 연결 문장을 찾을 수 있다. 원본 지식으로 설명을 메우면 실패다. |
| 주체·대상 명확성 | AI 도구의 제안과 본인의 판단을 구분한다. F2를 썼다면 삭제 대상은 변환된 글이며 녹음 파일 삭제로 오해되지 않는다. |
| 정보 선택 | 의미 없는 수치 나열이 없다. F3의 38초를 속도 개선으로 해석하지 않는다. 수치를 유지했다면 독자가 그 필요와 범위를 이해할 수 있어야 한다. |
| 사실 범위 | 시험을 실제 고객 운영, 일부 검증을 모든 오류 해결, 계획을 기존 숙련으로 바꾸지 않는다. |
| 필요한 대화 | 문항 1과 3의 부족한 개인 사실만 질문한다. 이미 주어진 사실을 재질문하거나 회사에 맞는 가치관 선택지를 정답처럼 제시하지 않는다. 문항 2는 계속 작성한다. |
| 실제 검토 | writing_brief와 reader_review에 구체적인 결론이 있다. 발견한 독해 문제는 구절·수정·재검토와 연결된다. 이슈를 억지로 만들거나 불명확한 글에 문제 없음으로 판정하지 않는다. |
| 조건 준수 | 전체 문항을 추적하고 실제 본문이 700자 이내다. 자동 검사가 불가능하면 실행 여부를 사실대로 보고한다. |

## 사용자 답변 후 재개

첫 응답 평가가 끝난 뒤 다음 가상 사용자 답변을 제공한다. 첫 요청에 미리 넣지 않는다.

> 1번은 게시판 경험을 쓸 수 있어. 처음에는 글만 고쳐도 전체 배포를 해야 했고, 나는 글 수정 때는 프로그램을 다시 배포하지 않겠다는 목표를 정했어. 내용과 코드가 같은 빌드 과정에 묶여 있어 갱신 경로를 나누는 게 어려웠어. 3번은 동료에게 피드백을 받고 내가 맡은 기능의 운영 결과까지 확인할 수 있는 조직을 원해.

추가 사실을 반영해 1번의 소재 적합성을 다시 판단하고 3번을 작성하는지 확인한다. 확인되지 않은 성과·동기를 추가하지 않으며 이전 부분초안을 보존한다. 소재 중복 때문에 2번을 조정할 수 있으나 관련 없는 유효 문장까지 임의로 다시 쓰지 않는다.

## 연결 검토 입력의 생성 평가

별도 입력의 첫 문항에는 목표 설정과 부하 시험의 목적이 이미 있다. 없는 정보처럼 재질문하지 않는다. 아래 평가는 앞의 정보 부족 시나리오와 분리한다.

- A 사례에서는 한 서버에서 두 작업을 제공할 목표, 동시 실행 시 검색 지연의 우려, 이를 확인하기 위한 시험, 관측한 지연에 따른 처리 변경, 재시험 결과가 연결돼야 한다. 시험 완료나 시험 도구 수리가 글의 중심으로 바뀌면 실패다.
- 배포 스크립트 정리와 로그 변경을 관련 근거 없이 성과로 덧붙이면 실패다. 시험 조건과 실제 운영 범위를 구분한다. 조건이 있는 시험 결과 자체를 불필요하다고 일괄 삭제해서도 안 된다.
- AI 활용을 직접 요구하는 둘째 문항에는 B의 AI 역할·본인의 구현과 판단·검증 결과가 필요하다. C를 같은 AI 활용 주장의 근거로 붙이면 실패다. 여러 경험을 무조건 금지하는 규칙으로 바꾸지 않는다.
- 분량 제한이 없더라도 중심 주장과 관계없는 경력이나 기술을 채워 넣지 않는다. 문장 수나 원문과의 표현 일치로 평가하지 않는다.

## 검토 실패와 정상 연결을 구분하는 대조 사례

생성 평가와 별도 대화에서 연결 검토 입력의 사실과 다음 후보들을 제공하고 문맥 검토를 요청한다. 판정 기준은 평가 대상에게 미리 주지 않는다. 기록된 체크박스가 모두 true여도 실제 본문으로 판단한다.

**후보 A**

> 한 서버에서 검색과 보고서를 제공하는 목표를 달성했습니다. 부하 발생 프로그램이 종료돼 여러 장비로 나눴습니다. 보고서 생성 개수를 제한했습니다. 5분 시험을 완료했고 검색은 1초 이내였습니다.

**후보 B**

> AI를 활용해 반복 업무를 자동화했습니다. 문의를 읽고 부서를 제안하도록 AI를 연결했습니다. 개인 게시판에서는 글 갱신과 코드 배포도 분리해 전체 재배포를 없앴습니다.

**후보 C**

> 한 서버에서 검색과 보고서 생성을 함께 제공하려면 보고서를 만드는 동안에도 검색이 지연되지 않아야 했습니다. 이를 확인하기 위해 두 작업을 동시에 실행하는 부하 시험을 구성했습니다. 보고서 3건을 동시에 만들 때 검색 응답이 최대 6초로 늘어나, 보고서는 한 건씩 처리하고 나머지는 기다리도록 바꿨습니다. 같은 조건에서 검색 응답이 1초 이내였고 대기한 보고서도 모두 생성됐습니다. 이는 동시 검색 요청 8개를 보낸 5분 시험에서 확인한 결과입니다.

평가자는 A에서 시험 목적·관측한 문제·조치의 이유 누락을, B에서 중심 주장과 두 번째 사례의 불일치를 찾아야 한다. 원본을 읽어 알게 된 연결을 본문에도 있다고 판정하면 실패다. C는 문제·시험 목적·조치·결과가 연결되므로 시험 결과가 있다는 이유로 같은 오류라고 판정해서는 안 된다. C의 평가 범위는 이 연결이며 전체 자소서의 자동 합격을 뜻하지 않는다. 실제 구절과 빠진 정보, 수정 후 앞뒤 연결로 판단 근거를 남긴다.

기존 숫자·대상 오류도 별도로 검토한다.

> 높은 목표였던 24개 중 12개를 연결했습니다. 식별자 12개로 16개를 처리했고 480초 해석에 성공했습니다. 초기 분석은 안전하다고 판단했으나 50초가 삭제됐습니다. 갱신은 38초로 개선했습니다.

목표 축소의 정당화, 수치의 대상 부재, 판단 주체와 삭제 대상 불명확, 비교 근거 없는 개선을 각각 찾아야 한다. 표현·분량 검사만 통과시키거나 없는 사실을 만들어 고치면 실패다.

## 결과와 종료 기준

각 항목은 통과·실패·미실행으로 기록하고 판단에 사용한 실제 문장이나 질문을 함께 남긴다. 전체 평균 점수로 사실 오류나 문항 부적합을 숨기지 않는다. 한 번만 잘 나온 결과를 일관성 확보로 보고하지 않는다. 실패를 고친 뒤에는 동일 입력으로 새 대화 평가를 다시 수행한다. 다른 환경에서 미실행한 결과는 검증된 것으로 확대하지 않는다.

```text
스킬 커밋 / 입력 파일 해시:
환경 / 모델·설정 / 가용 도구 / 훅 / 템플릿 버전:
실행 번호 / 대화 식별자 / 실행 시각:
초안·설계·검토 기록 위치:
자동 계약 테스트 결과:
첫 응답 항목별 판정과 실제 구절:
추가 답변 후 재개 결과:
생성 평가 / 결함 발견 평가 / 정상 연결 구분 결과:
대조 사례에서 발견·누락한 이슈와 실제 연결 구절:
반복 실행별 공통 실패와 편차:
미실행 환경과 남은 확인:
```
