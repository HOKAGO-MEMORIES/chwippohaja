# 판단과 배움 작성용 가상 자료

회사·서비스·경험은 모두 가상이다. 실제 취업 폴더와 외부 서비스에 저장하지 않는다.

## 사용자 요청

취뽀하자 스킬로 아래 자료를 사용해 가상회사 이음정비의 IT개발 자소서 초안을 작성해줘. 기업 조사와 문항 수집은 끝났어. 주어진 기업 방향에서 내가 기여할 수 있는 일을 지원동기로 제안해줘. 각 문항은 소제목·공백 포함 800자 이내이며, 정중한 서술식으로 작성해줘. 필요한 파일은 임시 워크스페이스에 저장해줘.

1. 이음정비에 지원한 이유와 입사 후 기여하고 싶은 일을 설명해주세요.
2. 새로운 기술을 학습하고 문제를 개선한 경험과 그 과정에서 배운 점을 설명해주세요.
3. 원칙이나 기준을 지키기 어려웠던 상황과 대처한 방법을 설명해주세요.
4. 동료와 협력해 공동의 업무를 진행한 경험을 설명해주세요.

## 제공된 기업 조사

가상 공식 발표: 이음정비는 여러 지점이 같은 장비의 수리를 이어 맡을 때 진단과 처리 이력이 누락되지 않도록, 지점별 기록을 '이음정비 기록실'로 통합하는 사업을 진행하고 있다. 직원이 이전 작업을 확인하고 다음 담당자에게 인계하는 시간을 줄이는 것이 목적이다. IT개발 직무는 이 업무 시스템의 개발과 운영을 담당한다. 내부 구현 기술과 경쟁사 대비 우위는 공개되지 않았다.

## 확인된 개인 경험

### A. 수리 동아리의 인계 기록

- 같은 장비를 여러 사람이 이어 수리했지만 개인 메모에 기록이 흩어져 이전 조치를 다시 물어야 했다.
- 본인은 공통 인계 화면을 만들고, 작업자가 원래 남긴 메모와 이후 수정 이력을 함께 확인할 수 있게 했다.
- 동료와 인계할 항목을 정하고 실제 인계 때 사용했다. 이전 담당자의 조치와 수정 이유를 화면에서 찾아볼 수 있게 됐다. 시간 절감률은 측정하지 않았다.
- 개인적으로 가상회사 서비스를 이용하거나 회사에 오래 관심을 가졌다는 기록은 없다.

### B. 인계 화면의 캐시 갱신 학습

- 기록을 수정한 뒤 DB에는 새 내용이 저장됐지만 조회 화면에는 이전 내용이 남았다.
- 본인은 프레임워크 문서를 읽고 작은 예제로 화면 경로별 갱신과 데이터 태그별 갱신을 비교했다. 여러 화면이 같은 장비 기록을 공유한다는 점을 확인했다.
- 캐시를 사용하지 않는 방법도 검토했다. 오래된 값을 남기지 않는 데는 도움이 되지만 매번 원본 데이터를 조회해야 하므로 조회 부하가 커질 수 있다고 판단했다. 실제 부하 증가율은 측정하지 않았다.
- 공통 데이터 태그를 갱신하는 방식을 선택해 기록 저장 후 호출했다. 갱신 신호가 실패할 때를 대비해 만료 시간도 유지했다. 수정한 기록이 관련 화면에 반영되는 것을 확인했다.
- 본인은 당시 선택을 돌아보며 최신성만 해결하는 것보다 기존의 조회 효율도 유지하는 방법을 비교해야 한다는 점을 배웠다고 설명했다.

### C. 협력자의 한시적 기록 접근

- 처음에는 동아리 회원만 장비 기록에 접근했다. 원칙은 담당 업무에 필요한 사람에게만 기록을 허용하는 것이었다.
- 외부 협력자가 장비 수리에 참여하게 되면서 기존 권한으로는 함께 기록을 확인할 수 없었다.
- 링크를 아는 사람 모두에게 공개하면 매번 권한을 설정하지 않아도 됐지만, 본인은 해당 장비 작업에 참여하는 협력자만 초대하고 작업이 끝나면 접근 권한을 회수했다.
- 협력자가 바뀔 때마다 담당자를 확인하고 초대·회수를 반복해야 했다. 급한 장애, 금전적 손해, 실제 정보 유출은 없었다.

### D. 동료의 화면 개발을 위한 인계 형식 합의

- 본인이 조회 기능을 개발하는 동안 동료는 화면 개발을 맡았다. 동료가 실제 응답을 기다리느라 화면 연결 작업을 진행하지 못한다고 알렸다.
- 본인은 진행 중인 상세 조회 구현을 잠시 미루고, 동료와 필요한 필드와 비어 있는 값의 처리 방식을 논의했다.
- 합의한 예시 응답을 먼저 전달했고 동료는 이를 사용해 화면 개발을 이어갔다. 이후 실제 응답을 연결하며 둘이 차이를 확인했다.
- 본인은 자기 기능의 완성 순서만 생각하기보다 동료가 다음 작업을 시작하는 데 필요한 정보를 먼저 제공하는 것이 중요했다고 설명했다. 일정 단축 수치는 없다.
