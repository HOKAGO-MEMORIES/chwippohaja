# 연결 검토용 가상 자료

회사·프로젝트·수치는 모두 가상이다. 실제 취업 자료와 외부 서비스에 저장하지 않는다.

## 사용자 요청

취뽀하자로 기존 자료를 사용해 아래 두 자소서 초안을 작성해줘. 공고 조사와 문항 수집은 끝났어. 분량 제한은 없고 정중한 서술식으로 써줘. 외부 저장이나 실제 서비스 접속은 필요 없어.

회사: 가상회사 모아업무. 직무: 반복 업무 분석, 자동화 개발 및 운영.

1. 높은 수준의 목표를 설정하고 달성한 경험을 설명해주세요.
2. AI를 활용해 반복 업무를 자동화한 경험과 본인이 맡은 역할을 설명해주세요.

## 확인된 사실

### A. 한 서버에서 검색과 보고서 생성을 함께 제공한 프로젝트

- 처음에는 문서 검색과 보고서 생성이 각각 동작했다. 본인은 비용 제약 때문에 한 대의 서버에서 두 기능을 동시에 제공하겠다는 목표를 정했다.
- 보고서 생성은 계산량이 많고 검색은 즉시 응답해야 했다. 두 작업을 동시에 수행했을 때 검색이 지연될지 확인할 필요가 있었다.
- 본인은 동시 검색 요청과 보고서 생성을 재현하는 부하 시험을 구성했다. 첫 시도에서는 부하 발생 프로그램이 먼저 종료돼 목표 조건을 재현하지 못했다.
- 부하 발생 프로그램을 여러 장비로 나누자 시험을 진행할 수 있었다. 보고서 3건이 동시에 생성될 때 검색 응답이 최대 6초로 늘어났다.
- 보고서를 기다리게 할 수 있다는 사용자 확인을 받아, 동시에 생성하는 보고서를 1건으로 제한하고 나머지는 대기열에서 순서대로 처리했다.
- 같은 시험 조건에서 검색 응답은 1초 이내였고 대기한 보고서도 모두 생성됐다. 검색 요청 8개를 동시에 보낸 5분 시험의 결과다. 일반적인 최대 처리량은 확인하지 않았다.
- 본인은 배포 스크립트 정리와 로그 보관 기간 변경도 수행했다. 이 변경에 대한 성능 개선 측정은 없다.

### B. AI로 문의를 분류한 경험

- 담당자가 문의 문장을 읽고 담당 부서를 정하는 작업을 반복하고 있었다.
- 본인은 과거 문의와 담당자 확인 결과로 분류 예시를 만들고 LLM API를 연결했다. AI가 부서와 분류 이유를 제안하면 담당자가 확인하는 흐름을 구현했다.
- 여러 부서에 걸친 문의에서 AI가 잘못된 부서를 단정하는 사례를 발견했다. 본인은 이런 문의는 부서를 자동 확정하지 않고 확인 목록으로 보내도록 수정했다.
- 담당자가 검토한 시험 문의 20건에서 명확한 문의 15건의 분류 제안이 확인 결과와 일치했고, 복합 문의 5건은 확인 목록으로 전달됐다. 확인 전 실제 고객에게 답변을 발송하지 않았다.
- 업무 시간 절감률과 상시 정확도는 측정하지 않았다.

### C. 개인 게시판의 갱신 자동화

- 글을 고칠 때 프로그램 전체를 다시 배포해야 했다. 본인이 글 갱신과 코드 배포를 분리해 내용 수정 때 전체 배포가 필요 없어졌다.
- 구현에는 일반 프로그램 코드와 예약 작업을 사용했다. AI를 사용했다는 기록은 없다.
