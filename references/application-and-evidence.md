# 지원서와 증빙

지원 폼의 개인정보, 학력, 경험과 첨부 자료를 정리할 때 읽는다.

## 작업 범위

작성 작업은 두 범위로 나뉜다.

### 자소서만

- 자소서 문항, 글자 수와 필수 여부만 확보한다.
- 자소설닷컴의 직무별 문항 화면을 우선한다.
- 개인정보, 학력, 경력과 첨부 입력 항목은 수집하지 않는다.
- 공식 지원 페이지 로그인과 지원서 초안 생성을 요구하지 않는다.

### 지원서 전체

- 자소서 작업에 기본정보, 학력, 경력, 경험, 자격, 어학, 동의와 첨부 조건을 더한 상위 범위다.
- 사용자가 `지원서 전체`, `전체 입력 초안` 또는 같은 의미를 명시했을 때 선택한다.
- 기업 공식 지원 페이지에서 대상 직무를 선택한 뒤 실제 입력 순서, 필드명, 필수 여부, 선택지, 글자 수, 파일 형식과 용량 조건을 확인한다.
- 사용자가 범위를 명시하지 않았고 요청이 모호하면 `자소서만`과 `지원서 전체` 중 하나를 선택하게 한다.

자소서만 진행하다가 지원서 전체로 확장할 수 있다. 기존 문항, 소재와 작성본을 다시 만들지 않고 재사용한다.

지원서 전체라는 범위는 하나의 합본 파일을 뜻하지 않는다. 자소서 답변과 그 밖의 지원서 입력값은 서로 다른 파일로 저장하고 독립적으로 수정한다.

## 공식 지원 페이지 경계

- 로그인은 사용자가 직접 수행한다. 비밀번호, 쿠키와 세션 값을 요청하거나 저장하지 않는다.
- 항목을 보기 위해 지원서 생성, 임시 저장이나 지원 시작 기록이 필요하면 실행 전에 외부 상태 변화와 대상을 알리고 승인을 받는다.
- 읽기 요청만으로 개인정보를 입력하거나 임시 저장하지 않는다.
- 마지막 제출 버튼과 지원 취소처럼 되돌리기 어려운 동작은 별도의 명시적 요청 없이는 수행하지 않는다.

## 지원서 전체 산출물

확인한 입력 구조와 실제 작성값을 분리한다.

```text
01_공고_JD/
└── 회사명_직무_지원서_항목.md

02_작성중/
├── NN_회사명_직무_자소서_작성본.md
└── NN_회사명_직무_지원서_작성본.md
```

`지원서_항목.md`에는 외부 화면에서 확인한 항목과 조건만 기록한다.

- 화면의 섹션과 입력 순서
- 필드명과 필수 여부
- 선택지와 형식 제한
- 자소서 문항과 글자 수
- 증빙 및 포트폴리오 첨부 조건
- 출처와 확인일
- 확인하지 못한 항목

`자소서_작성본.md`에는 자소서 문항 원문, 답변, 글자 수와 검증 상태를 기록한다.

`지원서_작성본.md`에는 자소서를 제외한 붙여넣을 값, 근거 자료, `확정`, `TBD`, `해당 없음` 상태와 최종 사용자 확인 사항을 기록한다. 자소서 문항은 중복해서 싣지 않고 채택한 자소서 작성본의 상대 링크와 버전만 적는다. 민감한 값은 실제 입력에 필요하고 사용자가 로컬 보관을 선택한 범위에서만 기록한다.

공식 지원서에 자소서 문항이 없으면 빈 자소서 파일을 만들지 않는다. 이미 자소서만 모드에서 작성한 파일이 있으면 새로 복사하지 않고 채택된 최신 버전을 연결한다.

## 입력 원칙

- 지원서 안내와 실제 입력 화면의 지시를 최우선으로 한다.
- 사용자가 제공한 성적표, 스프레드시트와 증빙을 사실 원본으로 사용한다.
- 편입, 복수전공과 학점 기준처럼 결과를 바꾸는 조건은 확인된 사실만 반영한다.
- 값이 불명확하면 `TBD`와 확인 질문을 남긴다.
- 계산 결과와 붙여넣기용 문자열을 분리해 제공한다.

## 학력과 학점

1. 지원 시점의 성적표를 기준으로 총 이수학점과 평균학점을 확인한다.
2. 학년별 전공은 성적표의 분류와 공고의 포함 범위를 따른다.
3. P/F 과목의 목록 기재와 학점 계산 포함 여부는 지원 안내에 따른다.
4. 과목명, 성적, 학점과 가중 평균 계산 근거를 보존한다.
5. 반올림 자리와 기준 평점은 입력 화면을 따른다.
6. 최종 값은 성적표 또는 사용자가 확인한 스프레드시트와 다시 대조한다.

지원 안내가 다른 규칙을 제시하면 이 일반 규칙보다 지원 안내를 우선한다.

## 경험

교육, 경력과 활동은 다음 값을 확인한다.

- 소속
- 역할과 직위
- 시작과 종료 시점
- 실제 수행 내용
- 팀 규모와 본인 담당
- 결과와 검증 가능한 수치

기업 맞춤 표현은 회사별 작성본에서만 만든다.

## 수상과 자격

- 상장 또는 증명서 첨부가 필수인데 파일이 없다면 임의로 입력하지 않는다.
- 아직 발급되지 않은 수상은 발급 상태와 공고의 첨부 필수 여부를 확인한다.
- 유효기간이 있는 증명서는 제출 시점의 유효성을 확인한다.
- 한 PDF에 여러 문서가 있을 때 일부만 필요한 경우 원본을 보존하고 목적이 분명한 복사본을 만든다.

## 민감서류

주민등록, 병역, 보험과 고용 이력처럼 민감한 서류는 명시적 제출 요구가 있을 때만 사용한다.

- 불필요한 복사본을 만들지 않는다.
- 공개 저장소, 공통 템플릿과 자소서 소재 문서에 넣지 않는다.
- 제출 대상과 요구 범위를 확인한 뒤 최소한만 첨부한다.

## 산출물

지원서 전체 모드의 두 작성본은 회사의 `02_작성중`에 각각 번호가 붙은 Markdown으로 저장한다.

- 자소서 작성본: 문항, 답변, 글자 수와 검증 상태
- 지원서 작성본: 자소서를 제외한 입력값 요약과 붙여넣기용 문자열
- 지원서 작성본: 계산 근거, 증빙 파일 위치와 첨부 조건
- 지원서 작성본: 미확인 항목과 사용자가 최종 확인할 항목

별도 이력서 업로드가 필요하면 이력서 파일도 `02_작성중`에서 버전 관리하되 두 기본 작성본을 대체하지 않는다. 해당 이력서 링크는 지원서 작성본의 첨부 자료 목록과 Notion 본문에 기록한다. 기존 Notion 데이터베이스에 별도 이력서 전용 속성이 있을 때만 그 속성에도 연결한다.

## Notion 연결

- 자소서 작성본의 실제 Drive URL은 `자소서 작성본` 속성에 연결한다.
- 자소서를 제외한 지원서 작성본의 실제 Drive URL은 `지원서 작성본` 의미의 속성에 연결한다.
- 기존 데이터베이스의 `이력서 작성본`이 자소서 외 지원서 작성본을 뜻한다고 확인된 환경에서는 이를 대응 속성으로 사용할 수 있다.
- 두 파일을 하나로 합쳐 같은 URL을 두 속성에 넣지 않는다.
- 수정본을 채택하면 해당 파일의 동기화와 실제 Drive URL을 확인한 뒤 그 링크만 갱신하고 이전 버전 파일은 보존한다.
