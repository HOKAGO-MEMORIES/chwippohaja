# 지원서와 증빙

지원 폼의 개인정보, 학력, 경험과 첨부 자료를 정리할 때 읽는다.

## 작업 범위

작성 작업은 두 범위로 나뉜다.

### 자소서만

- 자소서 문항, 글자 수와 필수 여부만 확보한다.
- 자소설닷컴의 직무별 문항 화면을 우선한다.
- 개인정보, 학력, 경력과 첨부 입력 항목은 수집하지 않는다.
- 공식 지원 페이지 로그인과 지원서 초안 생성을 요구하지 않는다.

### 지원서 전체

- 자소서 작업에 기본정보, 학력, 경력, 경험, 자격, 어학, 동의와 첨부 조건을 더한 상위 범위다.
- 사용자가 `지원서 전체`, `전체 입력 초안` 또는 같은 의미를 명시했을 때 선택한다.
- 기업 공식 지원 페이지에서 대상 직무를 선택한 뒤 실제 입력 순서, 필드명, 필수 여부, 선택지, 글자 수, 파일 형식과 용량 조건을 확인한다. 화면에 이미 입력된 값은 수집 대상이 아니다.
- 기본 결과물은 사용자가 공식 화면에 직접 복사해 입력할 수 있도록 값이 채워진 Markdown 작성본이다. 화면 자동 입력은 지원서 전체 범위에 자동으로 포함되지 않는다.
- 사용자가 범위를 명시하지 않았고 요청이 모호하면 `자소서만`과 `지원서 전체` 중 하나를 선택하게 한다.

자소서만 진행하다가 지원서 전체로 확장할 수 있다. 기존 문항, 소재와 작성본을 다시 만들지 않고 재사용한다.

지원서 전체라는 범위는 하나의 합본 파일을 뜻하지 않는다. 자소서 답변과 그 밖의 지원서 입력값은 서로 다른 파일로 저장하고 독립적으로 수정한다.

## 공식 지원 페이지 경계

- 로그인은 사용자가 직접 수행한다. 비밀번호, 쿠키와 세션 값을 요청하거나 저장하지 않는다.
- 항목을 보기 위해 지원서 생성, 임시 저장이나 지원 시작 기록이 필요하면 실행 전에 외부 상태 변화와 대상을 알리고 승인을 받는다.
- 읽기 요청만으로 개인정보를 입력하거나 임시 저장하지 않는다.
- 구조 수집 단계에서 채워진 지원서를 읽을 때 입력 요소의 현재 값, 첨부 파일의 개인 식별 정보와 자동 완성 정보를 가져오지 않는다.
- 구조 수집 단계의 브라우저 작업은 라벨, 안내문, 필수 표시, 선택지와 형식 제한만 대상으로 삼는다. 입력값을 반환하는 속성이나 동작은 사용하지 않는다.
- 마지막 제출 버튼과 지원 취소처럼 되돌리기 어려운 동작은 별도의 명시적 요청 없이는 수행하지 않는다.

## 구조 수집과 값 작성의 분리

`지원서 전체 가져오기`의 기본 의미는 지원서 구조 수집이다. 현재 화면에 저장된 값을 복제하는 작업이 아니다.

- `지원서_항목.md`에는 섹션, 필드명, 필수 여부, 선택지, 입력 제한과 첨부 조건만 기록한다.
- 값이 이미 채워져 있어도 빈 화면을 분석한 것처럼 구조만 기록한다.
- 일반 개인정보 입력란은 항목과 형식만 남기고 현재 값을 기록하지 않는다.
- 주민등록번호, 외국인등록번호, 여권번호, 계좌 정보, 인증 정보, 상세 주소, 개인 연락처, 생년월일과 건강, 장애 및 보훈 관련 값은 민감정보로 취급한다.
- 민감정보 입력란은 작성본에 실제 값을 쓰지 않고 `사용자 직접 입력`으로 표시한다.
- 사용자에게 확인된 학력, 경력, 프로젝트, 자격과 어학 정보는 이후 작성 단계에서 공통자료를 근거로 별도 지원서 작성본에 넣을 수 있다. 공식 지원 화면에 저장된 값을 원본으로 복사하지 않는다.
- 사용자가 실제 폼 입력까지 명시적으로 요청한 경우에도 민감정보는 화면에 필요한 최소 범위로만 입력하고 로컬 작성본, Notion과 진행 보고에 복제하지 않는다.

## 지원서 전체 산출물

확인한 입력 구조와 실제 작성값을 분리한다.

```text
01_공고_JD/
└── 회사명_직무_지원서_항목.md

02_작성중/
├── NN_회사명_직무_자소서_작성본.md
└── NN_회사명_직무_지원서_작성본.md
```

`지원서_항목.md`에는 외부 화면에서 확인한 항목과 조건만 기록한다.

- 화면의 섹션과 입력 순서
- 필드명과 필수 여부
- 행 추가 화면과 조건부 하위 필드
- 선택지, 입력 형식, 단위와 형식 제한
- 날짜의 과거·현재·미래 허용 범위와 진행 중 항목 처리 방식
- 선택에 따라 나타나거나 자동으로 정해지는 연동 필드
- 자소서 문항과 글자 수
- 증빙 및 포트폴리오 첨부 조건
- 출처와 확인일
- 확인하지 못한 항목
- 민감정보 입력란의 존재와 `사용자 직접 입력` 표시

`자소서_작성본.md`에는 자소서 문항 원문, 답변, 글자 수와 검증 상태를 기록한다.

`지원서_작성본.md`에는 자소서를 제외한 비민감 붙여넣기 값, 근거 자료, `확정`, `TBD`, `해당 없음`, `사용자 직접 입력` 상태와 최종 사용자 확인 사항을 기록한다. 자소서 문항은 중복해서 싣지 않고 채택한 자소서 작성본의 상대 링크와 버전만 적는다. 민감정보의 실제 값은 기록하지 않는다.

공식 지원서에 자소서 문항이 없으면 빈 자소서 파일을 만들지 않는다. 이미 자소서만 모드에서 작성한 파일이 있으면 새로 복사하지 않고 채택된 최신 버전을 연결한다.

## 전체 구조 사전 스캔

지원서 작성본을 만들기 전에 구조 수집을 한 번 마친다. 상위 화면에 보이는 라벨만으로 완료로 판단하지 않는다.

1. 모든 섹션과 탭을 실제 입력 순서대로 확인한다.
2. 학력, 경험, 교육, 자격처럼 행을 추가하는 항목은 추가 화면 내부의 필드와 필수 표시까지 확인한다.
3. 각 필드의 입력 종류, 최대 글자 수, 날짜 형식, 숫자 형식, 단위와 선택지를 기록한다.
4. 날짜 선택기는 미래 날짜 허용 여부와 진행 중 또는 종료일 공란 처리 여부를 확인한다.
5. 앞선 선택에 따라 나타나거나 자동 지정되는 발행처 같은 연동 필드는 그 조건을 기록한다.
6. 첨부 항목은 방식, 개수, 확장자, 용량과 필수 여부를 확인한다.
7. 자동 저장 안내와 구조 확인 과정에서 값 변경이 필요한지 확인한다.

읽기 전용으로 확인할 수 없는 연동 필드는 임의로 선택하지 않는다. 값 변경이 있어야만 확인할 수 있으면 `조건부 확인`으로 남기고, 사용자가 화면 변경을 승인한 입력 단계에서 검증한다. 구조를 모두 확인하지 못했으면 누락 범위를 적고 작성본의 대응 행을 `확정`으로 만들지 않는다.

## 기본 작업 방식

지원서 전체 모드의 기본은 사용자가 공식 폼을 직접 입력하는 보조 방식이다.

1. 공식 화면의 전체 구조를 스캔해 `지원서_항목.md`를 만든다.
2. 공통자료와 증빙을 대조해 자소서를 제외한 값을 `지원서_작성본.md`에 채운다.
3. 작성본은 공식 화면의 섹션과 필드 순서를 유지하고, 각 필드의 붙여넣기 값과 선택할 항목을 바로 찾을 수 있게 작성한다.
4. 민감정보는 실제 값을 기록하지 않고 사용자가 화면에서 직접 입력하도록 표시한다.
5. 사용자는 작성본을 보며 공식 화면에 복사해 입력한다.

공식 폼 자동 입력은 선택 기능이다. 사용자가 화면 입력까지 명시적으로 요청하지 않았다면 작성본 완성과 사용자 확인에서 작업을 끝낸다.

## 공통자료로 지원서 작성본 만들기

`지원서_항목.md`를 확보한 뒤 공통자료의 확인된 사실로 회사별 `지원서_작성본.md`를 새로 만든다. 이는 공통자료를 그대로 복제하는 작업이 아니라 지원 폼의 필드 의미와 형식에 맞춘 매핑 작업이다.

### 원본 우선순위

1. 사용자가 직접 확인한 `공통자료/지원서_공통정보.md` 또는 같은 목적의 기존 문서
2. 공통자료의 학력, 경력, 프로젝트, 교육, 자격, 어학과 수상 기록
3. 사용자가 지정한 성적표, 증빙과 포트폴리오 원본
4. 이번 지원 과정에서 사용자가 새로 확인한 사실

공식 지원 화면에 이미 저장된 값은 공통 사실의 원본으로 사용하지 않는다.

### 자동완성 규칙

1. `지원서_항목.md`의 필드를 공통자료의 같은 의미를 가진 사실과 대응시킨다. 필드명이 같다는 이유만으로 매핑하지 않고 단위, 기준일, 기간 형식과 선택지까지 확인한다.
2. 논리적 입력 행의 상태를 정하기 전에 그 행 안의 필수 하위 필드를 화면 구조 문서와 대조한다. 모든 필수 하위 필드에 값 또는 허용된 상태가 매핑되어야 행 전체를 `확정`으로 처리한다. 하나라도 빠지면 누락 필드를 명시하고 행 상태를 `TBD` 또는 해당 미확정 상태로 둔다.
3. 그대로 옮길 수 있는 확인된 비민감 사실은 `확정`으로 복사하고 원본 파일과 섹션을 출처로 남긴다.
4. 날짜 표기, 학점 기준과 글자 수처럼 화면 형식에 맞춘 변환값은 원본과 변환 근거를 함께 남긴다. 의미가 달라질 수 있는 변환은 자동 확정하지 않는다.
5. 하나의 필드에 여러 후보가 있거나 회사별 선택이 필요한 포트폴리오, 경험, 수상과 자격은 후보를 보여주고 사용자가 고르기 전까지 `TBD`로 남긴다.
6. 공통자료에 없는 항목은 추측하지 않고 `TBD`로 남긴다. 민감정보는 자료에서 찾지 않고 `사용자 직접 입력`으로 남긴다.
7. 자소서 문항과 답변은 복사하지 않고 채택한 `자소서_작성본.md`의 상대 링크와 버전만 기록한다.
8. 기존 회사별 작성본을 덮어쓰지 않고 `application_workspace.py next-draft` 규칙으로 다음 번호의 새 파일을 만든다.

### 작성본 구조

회사별 지원서 작성본에는 최소한 다음 내용을 기록한다.

- 대상 회사, 직무, 공고와 참조한 `지원서_항목.md`
- 채택한 자소서 작성본 링크와 버전
- 섹션별 필드명, 입력값 또는 상태
- 공식 화면 순서와 바로 복사할 붙여넣기 값
- 원본 사실과 화면 입력값의 구분
- 화면에서 별도로 입력하거나 선택하는 단위, 기준과 하위 필드
- 자동완성 값의 공통자료 출처
- 형식 변환과 계산 근거
- 첨부 후보와 선택 상태
- `확정`, `TBD`, `해당 없음`, `사용자 직접 입력`
- 최종 사용자 확인 항목

생성 후 자동완성된 항목 수, `TBD`, `사용자 직접 입력`과 충돌 항목 수를 보고한다. 새로 확인된 사실이 다른 지원서에도 재사용 가능하더라도 공통자료를 자동 갱신하지 않는다. 사용자 확인을 받은 뒤 별도 반영한다.

### 화면 입력 형식 매핑

작성본은 사람이 읽기 좋은 합성 표기와 실제 화면 입력값을 구분한다.

- 학점과 기준 평점, 점수와 만점, 시작일과 종료일처럼 화면에서 나뉜 값은 각각 별도 필드로 기록한다.
- `94.1/100`처럼 원본을 설명하는 표기를 숫자 입력란 하나에 그대로 넣지 않는다. 원본은 근거에 남기고 화면 입력값 `94.1`과 기준 선택값 `100`을 분리한다.
- 날짜는 화면 형식과 허용 범위를 따른다. 미래 종료일을 선택할 수 없는 화면에서 수료 예정일을 확정값으로 만들지 않는다.
- 선택형 값은 화면에 표시된 정확한 선택지와 대응시킨다. 일반적인 분류명이 실제 선택지에 없으면 비슷한 값을 임의로 확정하지 않는다.
- 연동 필드의 자동 지정 결과가 증빙과 일치하는지 확인하기 전에는 해당 행을 조건부 상태로 둔다.

## 입력 원칙

- 지원서 안내와 실제 입력 화면의 지시를 최우선으로 한다.
- 사용자가 제공한 성적표, 스프레드시트와 증빙을 사실 원본으로 사용한다.
- 편입, 복수전공과 학점 기준처럼 결과를 바꾸는 조건은 확인된 사실만 반영한다.
- 값이 불명확하면 `TBD`와 확인 질문을 남긴다.
- 계산 결과와 붙여넣기용 문자열을 분리해 제공한다.
- 지원 화면에서 읽은 기존 값과 공통자료에서 확인한 값을 혼동하지 않는다. 작성값은 공통자료 또는 사용자의 명시적 확인에서만 가져온다.

## 선택적 공식 지원 폼 자동 입력

공식 폼 입력은 구조 수집이나 Markdown 작성과 별개의 실행 단계다. 사용자가 `이 작성본을 지원 페이지에 입력해줘`처럼 화면 입력을 명시적으로 요청했을 때만 수행한다.

### 입력 원본

- `지원서_항목.md`는 필드 구조를 대조하는 기준이며 입력값의 출처가 아니다.
- 자소서 답변은 사용자가 채택한 최신 `자소서_작성본.md`에서 가져온다.
- 그 밖의 값은 사용자가 채택한 최신 `지원서_작성본.md`에서 가져온다.
- 두 작성본의 회사, 직무와 대상 공고가 현재 공식 지원 페이지와 일치하는지 먼저 확인한다.
- 작성본에서 상태가 `확정`인 값만 입력한다. `TBD`와 `사용자 직접 입력`은 입력하지 않으며 `해당 없음`은 화면에서 대응 선택지가 확인될 때만 선택한다.

### 실행 전 확인

입력 전에 사용자에게 다음 범위를 짧게 알린다.

- 사용할 두 작성본과 버전
- 입력할 섹션
- 건너뛸 `TBD`, `사용자 직접 입력`과 조건부 항목
- 업로드할 파일과 화면의 형식 및 용량 조건
- 사이트가 입력 즉시 자동 저장하는지 여부

자동 저장 사이트에서는 값 입력 자체가 외부 저장이다. 사용자가 공식 폼 입력을 요청했더라도 자동 저장 사실을 아직 알리지 않았다면 입력 전에 알리고 승인을 받는다.

### 화면 입력

1. 화면의 필드와 `지원서_항목.md`를 대조해 작성 이후 양식이 바뀌지 않았는지 확인한다.
2. 기존 값은 브라우저 안에서만 작성본과 비교하고 실제 문자열을 도구 출력, 문서와 보고에 반환하지 않는다. 결과는 `비어 있음`, `작성본과 동일함`, `작성본과 충돌함`으로만 판정한다.
3. 비어 있는 필드에는 작성본의 `확정` 값을 입력하고, 동일한 필드는 그대로 둔다.
4. 충돌한 필드는 자동으로 덮어쓰지 않는다. 필드명과 충돌 사실만 알리고 사용자의 선택을 기다린다.
5. 민감정보의 실제 값은 작성본에서 찾지 않는다. 사용자가 같은 세션에서 해당 필드의 입력을 명시적으로 요청하고 값을 제공한 경우에만 화면에 필요한 최소 범위로 사용한다.
6. 첨부는 작성본에서 채택된 실제 파일만 사용하고 확장자, 용량, 유효기간과 대상 서류를 다시 확인한다.
7. 입력 뒤 화면의 필수 누락, 형식 오류, 글자 수, 선택 상태와 첨부 성공 여부를 확인한다. 오류 보고에는 입력값을 포함하지 않는다.

### 저장과 제출 경계

- `입력해줘`는 화면에 값을 채우고 검증하는 권한이다. 임시저장과 최종제출 권한을 포함하지 않는다.
- `입력하고 임시저장해줘`처럼 저장까지 명시한 경우에만 임시저장을 실행하고 저장 완료 상태를 다시 확인한다.
- 최종제출은 입력이나 임시저장 요청과 분리한다. 제출 직전에 대상 회사, 직무, 채택한 작성본, 첨부와 남은 경고를 보여주고 사용자의 명시적 제출 요청을 받는다.
- 사이트가 다음 단계 이동과 동시에 저장하거나 지원 상태를 변경하면 해당 동작 전에 외부 변화와 되돌릴 수 있는지를 알린다.
- 입력 도중 화면 구조 변경, 세션 만료, 보안 인증, 충돌값 또는 예상하지 못한 필수 항목을 만나면 그 지점에서 중단한다.

입력 완료 보고에는 채운 섹션, 건너뛴 필드, 검증 오류, 임시저장 여부와 최종제출 미실행 여부만 기록한다. 민감정보와 실제 입력값은 반복하지 않는다.

## 학력과 학점

1. 지원 시점의 성적표를 기준으로 총 이수학점과 평균학점을 확인한다.
2. 학년별 전공은 성적표의 분류와 공고의 포함 범위를 따른다.
3. P/F 과목의 목록 기재와 학점 계산 포함 여부는 지원 안내에 따른다.
4. 과목명, 성적, 학점과 가중 평균 계산 근거를 보존한다.
5. 반올림 자리와 기준 평점은 입력 화면을 따른다.
6. 최종 값은 성적표 또는 사용자가 확인한 스프레드시트와 다시 대조한다.

지원 안내가 다른 규칙을 제시하면 이 일반 규칙보다 지원 안내를 우선한다.

## 경험

교육, 경력과 활동은 다음 값을 확인한다.

- 소속
- 역할과 직위
- 시작과 종료 시점
- 실제 수행 내용
- 팀 규모와 본인 담당
- 결과와 검증 가능한 수치

기업 맞춤 표현은 회사별 작성본에서만 만든다.

## 수상과 자격

- 상장 또는 증명서 첨부가 필수인데 파일이 없다면 임의로 입력하지 않는다.
- 아직 발급되지 않은 수상은 발급 상태와 공고의 첨부 필수 여부를 확인한다.
- 유효기간이 있는 증명서는 제출 시점의 유효성을 확인한다.
- 한 PDF에 여러 문서가 있을 때 일부만 필요한 경우 원본을 보존하고 목적이 분명한 복사본을 만든다.

## 민감서류

주민등록, 병역, 보험과 고용 이력처럼 민감한 서류는 명시적 제출 요구가 있을 때만 사용한다.

- 불필요한 복사본을 만들지 않는다.
- 공개 저장소, 공통 템플릿과 자소서 소재 문서에 넣지 않는다.
- 제출 대상과 요구 범위를 확인한 뒤 최소한만 첨부한다.
- 지원서 구조 수집 문서와 지원서 작성본에는 민감서류의 내용과 식별번호를 옮기지 않는다.

## 산출물

지원서 전체 모드의 두 작성본은 회사의 `02_작성중`에 각각 번호가 붙은 Markdown으로 저장한다.

- 자소서 작성본: 문항, 답변, 글자 수와 검증 상태
- 지원서 작성본: 자소서를 제외한 입력값 요약과 붙여넣기용 문자열
- 지원서 작성본: 계산 근거, 증빙 파일 위치와 첨부 조건
- 지원서 작성본: 미확인 항목과 사용자가 최종 확인할 항목

별도 이력서 업로드가 필요하면 이력서 파일도 `02_작성중`에서 버전 관리하되 두 기본 작성본을 대체하지 않는다. 해당 이력서 링크는 지원서 작성본의 첨부 자료 목록과 Notion 본문에 기록한다. 기존 Notion 데이터베이스에 별도 이력서 전용 속성이 있을 때만 그 속성에도 연결한다.

## Notion 연결

- 자소서 작성본의 실제 Drive URL은 `자소서 작성본` 속성에 연결한다.
- 자소서를 제외한 지원서 작성본의 실제 Drive URL은 `지원서 작성본` 의미의 속성에 연결한다.
- 기존 데이터베이스의 `이력서 작성본`이 자소서 외 지원서 작성본을 뜻한다고 확인된 환경에서는 이를 대응 속성으로 사용할 수 있다.
- 두 파일을 하나로 합쳐 같은 URL을 두 속성에 넣지 않는다.
- 수정본을 채택하면 해당 파일의 동기화와 실제 Drive URL을 확인한 뒤 그 링크만 갱신하고 이전 버전 파일은 보존한다.
