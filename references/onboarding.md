# 온보딩

워크스페이스 표식이 없거나 사용자가 처음 설정을 요청했을 때 읽는다.

## 원칙

- 운영체제와 무관한 표현인 `로컬 폴더`와 `동기화 폴더`를 사용한다.
- 경로는 자동으로 발견한 후보를 먼저 보여주고 직접 입력은 마지막 선택지로 둔다.
- Google Drive 동기화 폴더와 Codex Google Drive 연결 기능을 구분한다.
- Notion과 Google Drive 연결 기능은 선택 사항이며 로컬 전용 환경도 지원한다.
- 인증 정보, 계정, 외부 서비스 ID와 로컬 절대 경로를 공개 스킬이나 생성된 표식에 저장하지 않는다.
- 생성 계획을 보여주고 사용자의 승인을 받은 뒤에만 파일을 만든다.
- 기존 파일을 덮어쓰지 않는다.
- 스킬 지침만으로 전체 흐름을 수행한다. 로컬 `AGENTS.md`와 별도 운영 문서를 필수로 요구하거나 자동 생성하지 않는다.

## 상태 발견

스킬 루트의 `scripts/workspace_setup.py`를 사용한다.

```bash
python scripts/workspace_setup.py discover --path "현재 작업 경로"
```

결과 상태에 따라 진행한다.

| 상태 | 처리 |
| --- | --- |
| `configured` | 표식을 읽고 온보딩을 생략한다. |
| `adoptable` | 기존 취업 자료를 보존하면서 가져올지 묻는다. |
| `empty` | 새 온보딩을 시작한다. |
| `nonempty` | 다른 파일이 있는 폴더임을 알리고 가져오기 또는 다른 경로를 선택하게 한다. |
| `invalid` | 손상된 표식이나 파일 충돌을 보고하고 자동으로 수정하지 않는다. |

현재 작업 경로가 설정되지 않았더라도 상위 폴더에서 표식을 찾을 수 있으면 해당 워크스페이스를 사용한다.

## 선택 순서

### 1. 파일 저장 방식

다음 두 가지 중 하나를 선택하게 한다.

1. 로컬 폴더
2. Google Drive 동기화 폴더

Google Drive 동기화 폴더는 Drive for desktop이 운영체제에 제공하는 로컬 경로다. Codex Google Drive 연결 기능이 없어도 이 경로의 일반 파일을 읽고 쓸 수 있다.

### 2. 경로

`discover`가 반환한 운영체제별 후보를 먼저 제시한다.

- macOS: 현재 경로, Documents와 `Library/CloudStorage`에서 발견한 Drive 경로
- Windows: 현재 경로, Documents와 발견한 Drive 가상 드라이브 또는 동기화 폴더
- 그 외: 현재 경로와 Documents, 직접 선택

특정 드라이브 문자, 사용자 홈, 계정명과 언어별 `내 드라이브` 이름을 가정하지 않는다. 사용자가 최종 경로를 확인해야 한다.

### 3. 활성 시즌

`2026 하반기`처럼 회사 폴더를 묶을 이름을 받는다. 경로 구분자가 포함된 값은 사용하지 않는다.

### 4. 연결 기능

파일 저장 방식과 별도로 다음 기능의 사용 여부를 확인한다.

- Google Drive 연결 기능: 클라우드 검색, 실제 파일 URL과 메타데이터 확인
- Notion 연결 기능: `지원 공고` 검색, 생성과 상태 갱신

연결 기능이 보인다는 이유만으로 인증 완료를 가정하지 않는다. 읽기 전용 호출로 연결을 확인하고 성공했을 때만 `enabled`로 기록한다. 사용자가 나중에 연결하기로 했으면 `pending`, 사용하지 않으면 `disabled`로 기록한다.

Notion이나 Drive 연결이 실패해도 로컬 온보딩은 계속할 수 있다. 다만 연결 반영이 필요한 후속 작업은 완료로 처리하지 않는다.

연결 상태는 스킬 루트의 도구로 확인하고 갱신한다.

```bash
python scripts/workspace_setup.py integration-status --root "워크스페이스 경로"
python scripts/workspace_setup.py integration-status \
  --root "워크스페이스 경로" \
  --service notion \
  --set enabled
```

읽기 전용 연결 확인이 성공하기 전에는 `enabled`로 바꾸지 않는다. 이전에 연결됐지만 현재 인증이나 권한 문제로 사용할 수 없으면 `pending`으로 바꾼다. 사용자가 연결 기능을 사용하지 않기로 결정한 경우만 `disabled`로 바꾼다.

### Notion 대상 선택

Notion 사용을 선택하면 `지원 공고` 역할을 하는 기존 데이터베이스를 먼저 검색한다.

- 정확한 후보가 하나면 데이터 소스와 속성을 가져와 확인한다.
- 후보가 여러 개면 이름만으로 선택하지 않고 사용자에게 후보를 보여준다.
- 후보가 없으면 기존 페이지를 선택하거나 새 데이터베이스를 만들거나 Notion 없이 계속하는 선택지를 제공한다.
- 새 데이터베이스는 사용자가 선택한 부모 페이지와 생성 계획을 확인한 뒤에만 만든다.

새 데이터베이스의 최소 의미 항목은 공고 제목, 회사, 직무, 마감일, 지원 단계, 공고 원문, 기업 폴더와 주요 파일 링크다. 실제 속성명과 유형은 생성 계획에서 보여주며 기존 데이터베이스에 임의의 속성을 추가하지 않는다.

데이터베이스가 선택되거나 생성되면 검색, 한 항목 가져오기와 가능한 경우 쓰기 검증을 수행한다. 읽기만 가능하면 `enabled`로 기록하지 않고 제한 사항을 알린다.

### Google Drive 연결 확인

Google Drive 연결 기능은 사용자가 지정한 취업 폴더 또는 이름이 분명한 파일을 읽기 전용으로 검색해 확인한다. 로컬 동기화 폴더가 있다는 사실만으로 연결 기능 인증이 완료됐다고 판단하지 않는다. 실제 메타데이터와 URL을 가져올 수 있을 때만 `enabled`로 기록한다.

## 계획과 적용

선택이 끝나면 먼저 계획을 출력한다.

```bash
python scripts/workspace_setup.py plan \
  --root "선택한 경로" \
  --storage local \
  --season "2026 하반기" \
  --notion disabled \
  --drive-plugin disabled
```

기존 구조를 가져올 때만 `--adopt`를 추가한다. 생성할 폴더와 파일, 그대로 보존할 항목을 사용자에게 보여준다.

새 워크스페이스와 기존 환경 가져오기는 다르게 처리한다.

- 새 워크스페이스는 기본 폴더, 빈 공통자료와 작성 템플릿 및 활성 시즌을 생성한다.
- 기존 환경 가져오기는 기존 폴더 이름과 템플릿을 운영 구조로 채택한다. 표식과 사용자가 선택한 활성 시즌 폴더 외에는 만들지 않는다.
- `자격증_어학`, `경력_병역`처럼 의미가 분명한 통합 폴더가 있으면 그대로 사용하고 분리 폴더를 추가하지 않는다.
- 기존 폴더가 권장 이름과 달라도 역할을 알 수 있으면 이름을 바꾸거나 표준 폴더를 병렬로 만들지 않는다. 역할이 불명확할 때만 사용자에게 확인한다.
- 기존 환경의 `profile_status`는 파일 수로 추측하지 않는다. 사용자가 확인된 개인 사실이 없다고 하면 `empty`, 정리 중이면 `in_progress`, 현재 지원에 충분하다고 확인하면 `ready`를 계획에 명시한다.

사용자가 승인하면 같은 인자로 `apply`를 실행한다.

```bash
python scripts/workspace_setup.py apply \
  --root "선택한 경로" \
  --storage local \
  --season "2026 하반기" \
  --notion disabled \
  --drive-plugin disabled
```

Google Drive 동기화 폴더는 `--storage google-drive`를 사용한다.

기존 환경을 가져오는 예시는 다음과 같다.

```bash
python scripts/workspace_setup.py plan \
  --root "선택한 기존 경로" \
  --storage google-drive \
  --season "2026 하반기" \
  --notion pending \
  --drive-plugin enabled \
  --profile-status ready \
  --adopt
```

승인 후 같은 인자로 `apply`를 실행한다. `plan`과 `apply`가 제시하는 생성 항목이 다르면 적용하지 않는다.

## 완료 확인

적용 후 `discover`를 다시 실행하고 다음을 확인한다.

- 상태가 `configured`다.
- `.chwippohaja/workspace.json`에 절대 경로와 인증 정보가 없다.
- 새 워크스페이스의 `profile_status`가 `empty`다.
- 기존 환경은 사용자가 확인한 `profile_status`가 기록됐다.
- 새 워크스페이스에는 공통자료, 작성템플릿, 증빙서류와 활성 시즌 폴더가 있다.
- 기존 환경은 계획에 없던 기본 폴더와 템플릿이 생기지 않았다.
- 기존 파일이 변경되지 않았다.
- 요청한 연결 기능의 현재 상태를 사용자에게 알렸다.

기존 환경에 `AGENTS.md`나 운영 문서가 있으면 사용자 환경의 추가 규칙으로 보존한다. 해당 파일이 없는 상태도 정상이며 새로 만들지 않는다.

환경 온보딩이 끝나면 다음 선택지를 제시한다.

1. 기존 이력서 또는 포트폴리오 가져오기
2. 질문에 답하며 처음부터 정리하기
3. 지금은 건너뛰고 공고부터 등록하기

1번이나 2번을 선택하면 [정보 온보딩](profile-onboarding.md)을 읽는다. 3번은 공고 등록으로 이어가되 개인 사실이 필요한 작성 단계에서 정보 온보딩을 다시 제안한다.
