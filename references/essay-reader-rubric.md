# 본문 독자 검토

작성 설계와 사실 원본을 받지 않은 독자가 문항과 본문만 읽는 검토 기준이다. 내용 기준은 이 문서에서 관리한다. 원본과의 사실 대조, 사용자 선호 확인, 검사 기록 작성은 메인 작업이 뒤에서 수행한다.

## 입력과 검토 순서

입력은 문항 원문, 대응하는 본문, 분량·기업의 필수 형식 조건이다. 설계, 원본 소재, 기존 피드백, 통과 기록, 기대 판정은 읽지 않는다. 이 자료를 이미 받았다면 입력 제한이 지켜지지 않았음을 보고한다. 원본 확인이 필요한 내용은 사실 오류로 단정하지 않고 확인 필요로 분리한다.

1. 문항이 요구한 답을 확인한다. 본문은 요약하거나 순서를 바꾸기 전에 처음부터 원문 순서대로 읽는다.
2. 문장·문단을 넘어가며 읽기가 끊기는 지점과 정보의 필요성을 판단한다. 각 문장에 역할이 있어도 현재 위치에서 반복되거나 앞의 문제를 남긴 채 다른 주제로 옮겨가는지 본다. 의심되는 구절은 빼거나 옮겼을 때 문항의 답과 이해가 어떻게 달라지는지 비교하고 실제 구절과 영향을 남긴다. 뒤에서 관련 내용을 찾을 수 있다는 이유만으로 앞선 흐름을 통과시키지 않는다.
3. 그다음 본문에서 읽힌 전체 답을 짧게 요약하고 아래 네 기준으로 충족·부족·판단 유보를 구분한다. 요약에서 순서를 바꾸거나 핵심 관계를 임의로 보충해야 이해된다면 원문의 해당 지점을 이슈로 남긴다. 자연스럽게 추론되는 관계, 이해를 방해하지 않는 예고·회수와 단순한 배치 취향은 결함으로 만들지 않는다. 요약이 잘 읽힌다는 사실은 원문의 연결을 증명하지 않는다.
4. 발견한 이슈를 치명·권장·선택으로 나누고 충분한 답변은 그대로 인정한다. 사실인 행동이 있다는 것과 문항에 답한다는 것을 구분하며, 연결 문구를 추가하기 전에 해당 내용이 필요한지 판단한다. 부족한 사실이나 새 인과관계를 만들어 본문을 고치지 않는다. 검토만 요청받았다면 수정안을 본문에 적용하지 않는다.

문항별 출력은 원문 순서에서 발견한 이슈(구절·연결 또는 배치 문제·영향·등급), 읽힌 전체 답과 요구 충족 여부·본문 근거, 원본 확인 필요 사항이다. 이슈 수를 맞추지 않는다. 형식적인 통과 설명이나 체크포인트 JSON 작성은 독자의 일이 아니다.

## 네 가지 내용 기준

| 순서 | 본문에서 확인할 것 | 문제가 있으면 할 일 |
| --- | --- | --- |
| 소재 적합성 | 문항이 요구하는 것과 본문의 실제 행동·결과가 증명하는 것은 일치하는가?  | 주제만 관련되거나 다른 성과로 중심이 옮겨갔다면 주장·소재 선택부터 고친다. 문장이 자연스럽다는 이유로 적합하다고 인정하지 않는다. |
| 문장 연결 | 앞의 상황에서 다음 판단·행동이 필요한 이유와 그 행동에서 결과로 이어지는 관계가 이해되는가? | 실제 구절과 빠진 관계를 짚는다. 근거가 있는 목적·이유를 보완하거나 관련 없는 행동을 덜어낸다. 접속사 추가나 시간순 나열만으로 해결됐다고 판단하지 않는다. |
| 처음 읽는 사람의 이해 | 프로젝트를 모르는 사람이 서비스의 용도, 실행 주체·대상과 용어의 역할을 본문만으로 이해할 수 있는가? 우리끼리 아는 배경이 생략됐는가? | 필요한 배경과 관계를 보완한다. 기술명·수치의 역할을 판단해 필요한 내용은 남기고 불필요한 구현 이력은 덜어낸다. 쉬운 단어로 바꾼 뒤에도 같은 관계가 빠져 있으면 미해결이다. |
| 경험의 의미·강점·활용 | 행동에서 배움·판단 기준과 강점이 읽히는가? 문항이 활용을 요구한다면 어떤 업무에서 무엇을 어떻게 할지도 연결되는가? | 아래 경험의 의미 기준으로 사건과 배움, 강점과 활용을 연결한다. 성과 재요약, 근거 없는 강점 이름이나 일반적인 기여 다짐으로 대신하지 않는다. |


문항이 요구한 것과 본문이 증명한 범위를 비교한다. 주제가 관련되거나 성과가 있다는 이유만으로 통과시키지 않는다. 반대로 단순한 해결책, 특정 단어·별도 문단의 부재, 다른 회사에도 유용한 역량이라는 이유만으로 결함을 만들지 않는다. 명료성 문제와 소재를 더 강하게 만들 수 있다는 제안을 구분한다.

## 판정과 검토 종료

- **치명:** 핵심 답·본인 기여·인과관계를 이해할 수 없는 누락, 사실 오류·역할 과장, 필수 질문 누락·소재 부적합, 제출 조건 위반. 해결하거나 필요한 사실을 확인하기 전 해당 문항은 valid가 될 수 없다.
- **권장:** 핵심 답은 이해되지만 연결 근거·행동·결과가 약하거나 불필요한 설명이 남아 있음. 현재 자료로 고칠 수 있으면 수정한다. 남은 문제를 취향으로 낮추거나 기록에서 빼지 않는다.
- **선택:** 기본 이해와 문항 충족, 경험의 의미·강점·활용 연결이 확보된 상태에서의 강조 비중·설명 깊이·어휘·리듬·결론 어조. 별도 교훈·포부 문단으로 나눌지와 배치 위치도 여기에 해당한다. 사용자가 선택하면 반영하되 의미·사실 범위를 지키고, 미확인 감정이나 동기는 만들지 않는다.

경험의 의미는 아래 기준으로 판단한다. 문항이 직접 요구한 성찰·활용 계획의 누락은 치명이다. 경험형 답변이 행동 나열에 그치거나 제시한 배움·강점의 근거가 빠지면 권장으로 남긴다. 활용을 제시했다면 경험과의 연결을 확인한다. 문항이 활용을 요구하지 않고 경험의 판단 기준과 의미가 충분하면, 미래 업무 문장이 없다는 이유만으로 권장 이슈를 만들지 않는다. 연결이 실제 본문에 드러나면 별도 문단이나 정해진 표현은 필요 없다. 선택·행동에서 기준과 의미가 충분히 읽히면 결과로 끝낼 수 있다. 결말의 배움·기준 문장이 앞선 성과를 추상적으로 반복할 뿐인지도 확인한다. 경험이 필요 없는 단순 정보·계획 문항 또는 기업·사용자가 내용을 제한한 답변에는 불필요한 경험과 포부를 추가하지 않는다.

초안은 사실·역할·필수 질문·기본 맥락과 형식이 확인된 제안이다. 발견한 권장 문제는 현재 자료로 보완하고, 남기면 구절·이유·다음 조치를 명시한다. 초안이라는 이유로 치명 문제를 허용하거나 모든 검토를 통과시키려 권장 문제를 선택 사항으로 낮추지 않는다. 최종 후보는 권장 문제까지 처리한 뒤 제시한다.

검토 설명에서 근거가 약하거나 관계가 빠졌다고 판단했다면 해결한 본문 구절 또는 남은 이슈가 있어야 한다. 설명에는 미해결 문제가 있는데 issues·recommended_issues가 비어 있는 상태로 종료하지 않는다. 핵심 요구의 근거가 없으면 소재 재검토·사실 확인으로, 핵심 답의 설명이 약하면 권장 이슈로 처리한다. 자동 검사 통과로 이 내용 판정을 대체하지 않는다.

발견한 문제는 모두 판정하되 개수를 채우지 않는다. 수정 후에는 해결한 항목뿐 아니라 바뀐 답변 전체의 문항 적합성·맥락·사실 범위를 확인한다. 과거 해결 기록은 현재 본문을 재검토하지 않아도 된다는 근거가 아니다. 기본 요건이 충족되고 남은 결정이 선택 사항이면 초안을 제시하며, 완벽한 표현을 찾기 위한 반복 수정은 하지 않는다. 자동 검사기는 기록의 형식과 모순을 확인하며 글의 설득력을 판정하지 않는다.

## 경험의 의미·강점·활용

경험에서 확인된 판단 변화, 더 분명해진 기준, 이유가 연결된 느낀 점이나 이후 행동은 앞의 사건과 연결한다. 성과를 다시 설명하거나 “전체 흐름을 이해했다”처럼 어느 사례에도 붙는 말로 끝내지 않는다. 본문의 선택·비교·관찰에서 무엇을 이해했거나 중요하게 판단하게 됐는지, 그 이유가 실제 행동으로 뒷받침되는지 확인한다. 문제를 없애는 대안과 기존 장점을 유지하는 대안을 비교했다면, 결과의 재요약보다 그 선택에서 확인한 기준을 설명할 수 있다. 기술의 구체적인 동작을 이해한 배움도 유효하며 모든 경험을 가치관이나 극적인 생각의 변화로 바꾸지 않는다. 당시 판단·사후 이해·이후 행동·앞으로의 계획을 구분하고, JD 연결이나 포부로 경험의 의미를 대신하지 않는다.

경험형 답변은 행동에서 배움·판단 기준과 강점이 읽히도록 쓴다. 강점은 이름을 붙이는 대신 실제 판단·행동으로 보여줄 수 있다. 직무 활용을 묻는 문항에서는 **행동 → 배움·강점 → 활용할 업무와 구체적 행동**을 연결한다. 경험 자체를 묻는 문항에서는 실제로 얻은 기준, 적용한 행동이나 구체적 의미로 마칠 수 있다. 활용은 문항 요구와 분량에 맞춰 선택하며, 모든 답변에 미래 계획이나 회사명을 붙이지 않는다. '문제 해결 역량을 길러 회사에 기여하겠습니다'처럼 활용을 제시했지만 근거와 방법이 없는 경우에는 그 연결을 보완한다.

느낀 점·배운 점은 확인된 사용자 진술과 실제 선택·비교·관찰에서 드러난 이해를 바탕으로 설명한다. 새 감정, 깨달음의 계기나 행동 변화를 추정해 개인 사실로 만들지 않는다. 활용 계획은 향후 계획으로 구분하며, 이미 해 본 업무나 보장된 성과로 쓰지 않는다. 문항·사용자 요구로 일부 연결을 제외해야 한다면 기존 검토 기록에 이유를 남긴다. 등급과 검토 종료는 위 판정 기준을 따른다.


## 표현과 기록

내용 판정 후 첫 문장·리듬·배치가 이해를 방해하는지만 확인한다. 특정 결말, 극적인 변화, 매 문항의 별도 포부 문장을 강제하지 않는다. 문항과 사용자 요구상 필요한 활용이 빠진 경우와 표현 취향을 구분한다.

메인 작업은 독자 결과를 받은 뒤 원본 사실·역할·성과 범위 및 사용자 강조점과 대조한다. 기존 `reader_review.summary`에는 실제로 읽힌 답을, `question_fit`에는 요구·본문 근거·충족 범위·부족함을 옮긴다. `memorable_line`은 핵심 판단이나 결과를 보여주는 실제 구절로 기록하며, 인용 가능한 문장이 있다는 것을 내용 통과의 근거로 쓰지 않는다. 적절한 구절이 없으면 핵심 답이 드러나지 않는지 확인하고 실제 결함만 이슈로 남긴다.

독자의 지적은 자동 확정하지 않는다. 채택·수정·보류·비채택 이유를 해당 본문 구절에 근거해 남긴다. 원본에 설명이 있다는 사실만으로 본문 누락을 기각하지 않는다. 수정 후에는 바뀐 답변 전체를 같은 기준으로 다시 검토한다. 기존 통과 판정을 바꾸면 새 사실·이전 누락·해석 변경을 구분한다.
