# 전형 진행과 결과 관리

제출 뒤 시험·면접 안내, 응시 완료, 결과 또는 철회를 반영할 때 읽는다. 공고 한 건의 현재 상태와 다음 일정을 갱신하고 지난 이력을 보존한다. 이 모드만 요청되면 자소서 작성·재검토나 공고 재조사를 다시 실행하지 않는다.

## 기록의 기준

- 회사명만으로 항목을 선택하지 않고 공고·직무·지원 단위를 확인한다. 기본적으로 같은 공고 페이지를 계속 사용하며 시험마다 새 항목이나 데이터베이스를 만들지 않는다.
- 후속 전형의 현재 상태와 이력은 Notion을 기준으로 읽는다. 사용자가 직접 바꾼 값을 오래된 로컬 제출 상태로 되돌리지 않는다. Notion을 사용하지 않는 환경에서는 기업별 `03_검토기록/전형이력.md`에 같은 정보를 관리한다.
- 사용자 안내나 공식 개인별 안내로 확인된 사실만 반영한다. 예정일이 지났다는 이유로 응시 완료·합격·불합격을 추정하지 않는다. 공고의 공통 전형 예정일은 개인의 응시 확정일과 구분한다.
- 제출 PDF·채택 문안·제출일과 접수 증빙은 역사적 자료다. 전형 진행이나 이후 작성본 변경으로 덮어쓰지 않는다. `.application-state.json`의 submission은 제출 사실을 뜻하며 필기·면접 상태로 대체하지 않는다.

## 속성 대응

먼저 현재 데이터 소스와 실제 값을 읽고 의미가 같은 기존 속성을 사용한다. 아래 이름은 예시이며 이름을 맞추기 위해 속성을 재생성하지 않는다.

| 의미 | 속성 예시 | 관리 방식 |
| --- | --- | --- |
| 최초 서류 접수 마감 | 서류 마감일 / 마감일 | 원래 날짜 보존. 공식 마감 변경 시 변경 전후 이력 기록 |
| 도달한 전형 | 지원 단계 | 지원 완료, 코테, 역량검사, 필기시험, 면접, 최종 합격, 종료 등으로 구분. 기존 환경의 같은 의미 선택지 사용 |
| 그 전형의 진행 상황 | 전형 상태 | 준비 중, 일정 확정, 결과 대기, 합격, 불합격, 포기, 확인 필요 |
| 확정된 시험·면접 날짜 | 전형 일시 | 개인별 확정 안내로 입력. 응시 후 이력 보존 |
| 결과·안내를 확인할 날짜 | 다음 확인일 | 공식 발표 예정일 또는 사용자가 정한 관리 날짜. 실제 전형일과 구분 |
| 달력에 표시할 날짜 | 달력 표시일 | 상태에 따라 마감일·전형 일시·다음 확인일을 선택하는 날짜 수식 |
| 해야 할 행동 | 다음 할 일 | 시험 응시, 결과 확인, 면접 참석 등 짧은 문장 |
| 지난 일정과 결과 | 공고 본문의 전형 이력 | 날짜, 내용, 확인 근거를 누적 |

상태와 날짜의 의미는 속성 설명 또는 사용자용 안내에 남긴다. 속성이 부족하면 이미 승인된 구조 정리 범위에서 추가하고, 단순 일정 갱신 중에는 구조를 임의로 바꾸지 않는다. 회사별 시험 이름은 속성 대신 다음 할 일과 이력에 기록한다.

## 갱신 순서

1. 기존 공고의 속성·전형 이력과 새 안내를 함께 읽는다. 이미 반영된 같은 사실은 중복 추가하지 않는다.
2. 날짜를 교체하거나 비우기 전에 기존 일정의 날짜·시간대·내용·확인 근거를 이력에 보존한다. 예정, 응시 완료, 결과 확인을 구분한다. 완료일을 모르면 정리한 날을 완료일로 대신 쓰지 않는다.
3. 현재 전형과 진행 상태, 다음 할 일을 갱신한다. 응시 완료라면 해당 전형의 결과 대기, 합격 후 면접 안내라면 면접의 일정 확정 등으로 반영한다. 탈락은 종료·불합격, 제출 후 철회는 종료·포기처럼 구분하되 도달한 단계는 이력에 남긴다.
4. 서류 제출만 완료하고 후속 전형이 시작되지 않았다면 지원 완료·결과 대기를 유지하며 달력에는 원래 서류 마감일을 표시한다. 오늘, 제출 후 7일 또는 공통 발표 예정일로 표시 날짜를 일괄 교체하지 않는다. 지난 마감일만으로 제출 완료 건을 확인 필요로 바꾸지 않는다.
5. 실제 후속 전형 안내를 받으면 코테·역량검사·필기시험·면접 중 해당 단계와 전형 일시를 갱신한다. 공고의 공통 검사 기간만으로 개인 전형이 시작됐다고 판단하지 않는다. 회사별 검사 이름은 다음 할 일과 이력에 남긴다.
6. 응시 후 새 일정이 없으면 마지막 전형 날짜를 유지하고 결과 대기로 관리한다. 사용자가 별도로 결과 확인일 관리를 요청한 경우에만 다음 확인일을 사용하며 실제 일정과 구분한다. 날짜 경과만으로 확인일을 오늘이나 다음 주로 바꾸지 않는다.
7. 페이지와 메인 달력을 다시 읽어 과거 기록·서류 마감·제출 자료가 보존됐는지, 현재 상태·다음 행동·표시 날짜가 맞는지 확인한다.

예: 시험 예정일이 지난 것만 확인됐다면 기존 시험 날짜와 `실제 응시 여부 확인`을 유지한다. 사용자가 응시를 확인하면 이력에 완료를 남기고 결과 대기로 바꾸며, 다음 실제 일정이 확인될 때 날짜를 갱신한다.

## 달력과 목록

- 메인 달력은 달력 표시일을 기준으로 한다. 종료·미지원·최종 합격은 빈 날짜, 지원 예정·지원 완료는 마감일, 후속 전형은 전형 일시를 표시한다. 후속 전형의 날짜가 없고 사용자가 지정한 확인일이 있으면 그 날짜를 사용한다. 달력용 날짜는 수식이 선택하고 원본 마감일을 덮어쓰거나 전형 일시에 복제하지 않는다.
- 원래 서류 마감을 보는 달력은 별도 보기로 유지할 수 있다. 보기 추가는 같은 데이터 소스를 재사용한다.
- 다음 일정 하나를 바꾸면 이전 날짜의 달력 카드는 이동한다. 과거 모든 전형 날짜가 같은 달력에 동시에 남는다고 설명하지 않는다.
- 결과 대기 보기는 날짜가 없어도 표시한다. 확인 필요 보기는 지원 완료 건의 지난 서류 마감과 후속 전형의 확인 필요를 구분한다. 제출 완료 건은 마감일 경과만으로 경고하지 않는다. 고정된 오늘 날짜 필터를 설치하거나 매일 다음 확인일을 뒤로 미루는 수식을 쓰지 않는다.
- 메인 페이지의 연결된 달력과 원본 데이터베이스 보기는 서로 다를 수 있다. 실제 메인 달력의 보기 ID·날짜 기준·필터를 확인하고 변경 후 재조회한다.

## 기존 구조 정리

정리가 요청됐을 때만 수행한다. 사용 중인 값과 보기 설정을 확인하고 비어 있는 속성, 중복 의미, 대표 링크 누락을 구분한다. 삭제할 항목은 먼저 사용자에게 알리고, 값이 있으면 이력이나 대응 속성에 옮긴 뒤 재조회한다. 기존 속성 보존과 보기에서 숨기기로 목적을 달성할 수 있으면 불필요하게 삭제하지 않는다.

별도 시험 항목이 이미 있으면 날짜·설명·근거를 원래 공고에 보존한다. 원문은 원래 공고의 하위 페이지로 이동해 지원 건 목록에서 제외할 수 있다. 이동 전후 항목 수와 원문 접근 여부를 확인한다. 회사·직무 선택이 불명확하면 임의로 합치지 않는다.

## 보고와 재개

현재 전형·진행 상태·다음 행동·확정 날짜와 미확인 사항을 보고한다. 단순 상태 갱신은 자동 모니터링을 시작하지 않는다. 정기 확인은 별도로 요청된 자동화가 있을 때만 수행한다. 자료 보관과 링크 연결 대기는 [제출과 최종 점검](submission-and-checklist.md)의 재확인 절차를 따른다.
