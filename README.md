# 취뽀하자

한국 취업 지원을 공고 등록부터 최종 제출 자료 정리까지 이어서 관리하는 Codex 스킬입니다.

로컬 파일은 사실과 작성 원본으로 사용하고, Google Drive는 동기화와 파일 링크, Notion은 공고와 지원 상태의 인덱스로 사용합니다. 계정 ID와 개인 자료를 저장소에 넣지 않고 실행 시점에 현재 워크스페이스와 연결 서비스를 발견합니다.

## 지원 범위

- 공고와 JD 보관
- 공식 자료를 바탕으로 한 기업 리서치
- 같은 기업의 여러 공고와 공고 변경 이력 관리
- 지원 건 폴더 생성과 작성 번호 계산
- 회사별 작업 폴더 생성
- 지원서 입력 항목과 증빙 정리
- 자소서 소재 수집, 초안, 리뷰와 버전 관리
- 선택적인 `humanize-korean` 윤문
- 기업별 선택형 검토 기록 보관
- Drive 파일 링크 확인
- Notion 지원 단계와 주요 링크 관리
- 실제 제출 지원서와 접수 증빙 확보 및 보관

## 설치

저장소를 Codex 스킬 디렉터리에 복사하거나 심볼릭 링크로 연결합니다.

macOS와 Linux:

```bash
git clone https://github.com/<GitHub 사용자명>/chwippohaja.git
mkdir -p ~/.codex/skills
ln -s "$(pwd)/chwippohaja" ~/.codex/skills/chwippohaja
```

Windows에서는 저장소를 `%USERPROFILE%\.codex\skills\chwippohaja`에 복사하거나 디렉터리 연결로 추가합니다.

## 처음 시작

새 Codex 작업에서 다음처럼 요청합니다.

```text
$chwippohaja로 처음 설정해줘.
```

스킬은 기존 워크스페이스를 먼저 찾습니다. 없으면 다음 항목을 순서대로 선택합니다.

1. 로컬 폴더 또는 Google Drive 동기화 폴더
2. 자동으로 발견한 경로 후보 또는 사용자가 지정한 경로
3. 활성 시즌 이름
4. Google Drive와 Notion 연결 기능 사용 여부

생성 계획을 확인한 뒤 승인하면 공통자료, 작성템플릿, 증빙서류와 시즌 폴더를 만듭니다. 기존 파일은 덮어쓰지 않습니다.

기존 취업 자료를 가져오는 경우에는 기존 폴더와 템플릿을 그대로 채택합니다. 가져오기 과정에서는 표식과 필요한 활성 시즌 폴더만 만들며, 표준 폴더나 템플릿을 병렬로 추가하지 않습니다. 새 환경의 기본 증빙 구조는 `학력`, `자격증_어학`, `교육_수상`, `경력_병역`, `사진_서명`, `민감서류`입니다.

환경 설정 뒤에는 개인 사실을 준비하는 방식을 선택합니다.

1. 사용자가 선택한 기존 이력서 또는 포트폴리오에서 가져오기
2. 학력, 경력, 프로젝트와 기술을 한 영역씩 질문하며 정리하기
3. 정보 정리는 건너뛰고 첫 공고부터 등록하기

가져온 내용은 후보로 먼저 보여주며 사용자가 확인한 사실만 공통자료에 기록합니다. 건너뛰어도 공고와 JD 정리는 가능하지만, 이력서와 자소서 작성 전에는 필요한 사실을 확인합니다.

Codex에서 다음처럼 사용합니다.

```text
$chwippohaja로 이 공고를 등록하고 지원 준비를 시작해줘.
$chwippohaja로 기존 회사 자소서 작성 단계부터 이어서 진행해줘.
$chwippohaja로 제출 결과를 확인하고 최종 지원서와 접수 증빙을 확보해 Notion에 반영해줘.
```

작성 범위는 두 가지로 선택할 수 있습니다.

### 자소서만

자소설닷컴의 직무별 화면에서 자소서 문항과 글자 수를 확인하고 소재 선정, 작성 설계, 초안, 리뷰와 윤문을 진행합니다. 지원 화면이 허용하면 각 답변 첫 줄에 본문을 대표하는 `[핵심 요약 문구]` 하나를 두고 해당 문구까지 글자 수에 포함합니다. `전체 자소서 문항`을 요청해도 기업 지원 페이지의 개인정보나 학력 항목까지 확장하지 않습니다.

```text
$chwippohaja로 이 공고의 자소서 문항만 확인하고 초안을 준비해줘.
```

### 지원서 전체

기업 공식 지원 페이지에서 전체 입력 항목과 첨부 조건을 확인하고, 자소서 작성본과 자소서를 제외한 지원서 작성본을 따로 만듭니다. 지원서 작성본은 공식 화면 순서에 맞춰 값을 채운 복사·붙여넣기용 Markdown으로 제공하며 사용자가 직접 입력하는 방식을 기본으로 합니다. 채워진 화면에서도 현재 값은 가져오지 않고 항목 구조만 수집하며, 민감정보 입력란은 실제 값 대신 `사용자 직접 입력`으로 남깁니다. 자소서만 모드의 상위 범위이며 로그인은 사용자가 직접 수행합니다.

지원서 항목을 수집한 뒤에는 공통자료의 확인된 학력, 교육, 경력, 자격, 어학과 수상을 새 회사의 `지원서_작성본.md`에 자동으로 매핑합니다. 자동완성한 값에는 출처를 남기고, 회사별 선택이 필요하거나 확인되지 않은 값은 `TBD`로 둡니다. 연락처, 상세 주소와 등록번호 같은 민감정보는 공통자료에 저장하지 않습니다.

공식 폼 자동 입력은 선택 기능입니다. 사용자가 별도로 요청하면 채택한 두 작성본의 `확정` 값만 화면에 옮깁니다. `지원서_항목.md`는 입력 원본으로 사용하지 않으며, `TBD`와 `사용자 직접 입력`은 건너뜁니다. 기존 값과 충돌하면 덮어쓰지 않고 확인을 요청합니다. 값 입력, 임시저장과 최종제출은 각각 별도 단계입니다.

```text
$chwippohaja로 공식 지원 페이지의 전체 항목을 읽고 지원서 전체 초안을 준비해줘.

$chwippohaja로 채택한 지원서 작성본과 자소서 작성본을 공식 지원 페이지에 입력해줘. 임시저장과 최종제출은 하지 마.
```

## 실행 환경

- 온보딩에서 생성하거나 가져온 워크스페이스
- 개인 사실을 저장한 공통자료
- `.chwippohaja/workspace.json`의 정보 설정 상태
- 회사별 작업 폴더
- Notion 연결 기능
- Google Drive 연결 기능
- 선택 사항: `humanize-korean`

워크스페이스의 `AGENTS.md`와 별도 운영 문서는 선택 사항입니다. 존재하면 해당 환경의 추가 규칙으로 보존하고 읽지만, 없어도 스킬의 전체 흐름이 작동하며 온보딩에서 새로 만들지 않습니다.

Notion과 Google Drive 연결이 없는 환경에서는 로컬 작성 작업만 수행할 수 있으며, 연결 반영이 필요한 요청은 완료로 처리하지 않습니다.

Notion 사용을 선택했는데 기존 지원 관리 데이터베이스가 없으면 사용자가 선택한 페이지에 새 데이터베이스를 만드는 계획을 먼저 보여줍니다. Notion 사용을 유지하려면 데이터베이스가 필요하며, 사용자가 승인한 경우에만 생성하고 실제 읽기와 쓰기 권한을 확인한 뒤 연결 상태를 갱신합니다. 마감일 기준 달력 보기는 같은 데이터베이스에 추가하는 선택 사항입니다.

지원서 전체 모드에서도 산출물을 하나로 합치지 않습니다. `자소서 작성본`에는 문항과 답변을, `지원서 작성본`에는 자소서를 제외한 기본정보, 학력, 경험, 자격과 첨부 정보를 저장합니다. 두 파일은 각각 버전 관리하며 동기화된 실제 Drive URL을 Notion의 대응 링크에 연결합니다.

제출이 확인되면 공식 지원 페이지의 다운로드, 인쇄와 접수증 기능을 순서대로 확인해 실제 제출 지원서 PDF를 우선 확보합니다. 사이트가 지원서 PDF를 제공하지 않으면 접수증이나 완료 화면을 보관하고 그 사실을 Notion에 기록합니다. 자동 다운로드나 PDF 저장이 불가능할 때만 사용자에게 직접 파일 저장을 요청합니다.

## 개인정보

이 저장소에는 다음 값을 커밋하지 않습니다.

- 토큰, 쿠키와 OAuth 인증 파일
- 실제 Notion 페이지와 데이터베이스 ID
- 실제 Drive 파일과 폴더 ID
- 계정 이메일과 로컬 절대 경로
- 이력서, 자소서, 성적표와 증빙서류

로컬 전용 설정과 임시 윤문 결과는 `.gitignore`로 제외합니다. 보존할 검토 결과는 워크스페이스 최상단이 아니라 해당 기업의 선택형 `03_검토기록`에 둡니다.

