# 취업자료 운영 규칙

## 기준점

- 로컬 파일을 사실과 작성 원본으로 사용한다.
- `.chwippohaja/workspace.json`의 `active_season`을 현재 회사별 작업 폴더의 기준으로 사용한다.
- `.chwippohaja/workspace.json`의 `profile_status`는 개인 사실의 내용이 아니라 준비 상태만 나타낸다.
- Google Drive와 Notion은 설정된 경우에만 동기화, 링크와 지원 상태 관리에 사용한다.

## 폴더 역할

- `공통자료`: 기업과 무관한 확인된 개인 사실
- `작성템플릿`: 기업에 종속되지 않는 빈 양식과 체크리스트
- `증빙서류`: 학력, 자격, 어학, 교육, 수상, 경력과 제출 서류
- `활성 시즌/회사명/01_공고_JD`: 공고 원문, JD, 공고 분석과 기업 리서치
- `활성 시즌/회사명/02_작성중`: 기업별 작성본과 주요 수정본
- `활성 시즌/회사명/99_최종제출`: 실제 제출한 파일

## 작성과 버전

- 공통자료는 확인된 개인 사실을 추가하거나 정정할 때만 수정한다.
- 기존 이력서나 포트폴리오에서 추출한 내용은 사용자 확인 후에만 공통자료에 반영한다.
- 기업 맞춤 내용은 회사별 작성 폴더에서만 만든다.
- 작성 중 새 파일과 주요 수정본은 `01_`, `02_`, `03_`처럼 다음 번호를 사용한다.
- 기존 버전을 덮어쓰지 않는다. 사용자가 특정 파일의 소규모 수정을 명시한 경우만 예외로 한다.
- 같은 기업의 별도 지원 건은 공고 URL, 공고 ID, 직무와 제출 단위를 확인해 구분한다.
- 공고가 변경되거나 재제출한 경우 이전 원본과 제출 파일을 보존한다.

## 제출

- 실제 제출 PDF와 사용자의 제출 확인이 모두 있어야 지원 완료로 기록한다.
- 민감서류는 기업이 명시적으로 요구한 범위에서만 사용한다.
- 연결 서비스 반영이 실패하면 미반영 상태와 필요한 후속 작업을 남긴다.
