# Codex 작업 경계

작업 전에 `README_취업자료_운영규칙.md`와 `.chwippohaja/workspace.json`을 읽고 따른다.

## 공통자료

- `공통자료/경력_프로젝트_소재.md`에는 모든 기업의 이력서와 자소서에 공통으로 사용할 수 있는 확인된 개인 사실만 저장한다.
- 기업명, 직무, JD 해석, 지원 전략, 지원동기, 강조 순서와 글자 수 조건을 넣지 않는다.
- 확인되지 않은 내용은 추측하지 않고 `TBD`로 남긴다.
- 기존 문서에서 추출한 내용도 사용자가 확인하기 전에는 공통자료에 쓰지 않는다.

## 기업별 자료

- 공고, JD, 직무 분석과 기업 리서치는 회사 폴더의 `01_공고_JD`에 저장한다.
- 기업 맞춤 이력서, 자소서와 지원서 입력 초안은 `02_작성중`에 저장한다.
- `02_작성중`의 새 파일은 사용하지 않은 다음 두 자리 번호로 시작한다.
- 실제 제출한 파일만 `99_최종제출`에 저장한다.
- 같은 기업 폴더가 있어도 공고 URL, 공고 ID, 직무와 제출 단위를 확인하기 전에는 같은 지원 건으로 합치지 않는다.

## 연결 기능

- 새 공고를 등록할 때 Notion 사용이 설정되어 있으면 같은 작업에서 `지원 공고`를 생성하거나 갱신한다.
- Notion이나 Google Drive 연결 문제로 필요한 반영을 하지 못하면 완료로 보고하지 않는다.
- 토큰, 계정 정보와 외부 서비스 ID를 문서에 기록하지 않는다.
